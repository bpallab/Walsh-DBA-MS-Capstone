# Data dictionary

Key variables used in the study. Full column profiles (type, % missing, distinct values, example) are generated by notebook 01 into `results/tables/profile_*.csv`.

## ServiceNow incident event log (UCI 498) — 36 attributes
| Variable | Type | Description | Used for |
|---|---|---|---|
| number | Identifier | Incident identifier (case ID) | Joins |
| incident_state | Categorical | State at each event (New, Active, Resolved, Closed, …) | Event-to-incident reduction |
| category, subcategory, u_symptom | Categorical | Classification (anonymised codes) | D1 |
| impact, urgency, priority | Ordinal | Severity fields | D1 |
| assignment_group, assigned_to | Categorical | Team and person handling the incident | D5 |
| reassignment_count, reopen_count | Count | Times reassigned / reopened | Friction count |
| knowledge | Binary | Knowledge-base document used | D3 |
| contact_type, location, cmdb_ci | Categorical | Channel, location, configuration item | Features; graph |
| made_sla | Binary | Service-level target met | Outcome profile |
| opened_at, resolved_at, closed_at | Datetime | Timestamps (day-first) | Time to action |

All 36: number, incident_state, active, reassignment_count, reopen_count, sys_mod_count, made_sla, caller_id, opened_by, opened_at, sys_created_by, sys_created_at, sys_updated_by, sys_updated_at, contact_type, location, category, subcategory, u_symptom, cmdb_ci, impact, urgency, priority, assignment_group, assigned_to, knowledge, u_priority_confirmation, notify, problem_id, rfc, vendor, caused_by, closed_code, resolved_by, resolved_at, closed_at. Missing values are recorded as "?" and treated as unknown.

Derived: `friction_count` = reassignment_count + 1; `resolution_hours` = resolved_at − opened_at.

## Rabobank ITSM log (BPI Challenge 2014)
Column names are converted to snake_case by the loader (e.g. `CI Name (aff)` → `ci_name_aff`, `# Reassignments` → `n_reassignments`).
| Variable | Type | Description | Used for |
|---|---|---|---|
| Incident ID / Interaction ID / Change ID | Identifier | Case identifiers linking the three processes | Joins, graph |
| CI Name (aff), CI Type (aff) | Categorical | Configuration item affected | Graph; D5, D6 |
| Service Component WBS (aff) | Categorical | Service component affected | Graph; D5 |
| Impact, Urgency, Priority | Ordinal | ITIL severity | D1 |
| Category | Categorical | Incident vs request for information | D1 |
| KM number | Categorical | Knowledge article used | D3 |
| First Call Resolution | Binary | Resolved at first contact (interactions) | L1 volume |
| # Reassignments | Count | Times the incident changed team | Friction count |
| Closure Code | Categorical | How the case was closed | D4 (proxy) |
| Related Change | Identifier | Change related to the incident | D6 ground truth |
| Open / Resolved / Close Time; Actual Start/End | Datetime | Case and change timestamps | Time to action; D6 windows |

## Public Jira Dataset (v7)
| Variable | Type | Description | Used for |
|---|---|---|---|
| repository, project, key | Identifier | Source Jira instance, project, issue key | Joins; cross-organisation analysis |
| summary, description | Text | Ticket title and body | Model input |
| issuetype | Categorical | Bug, Task, Improvement, … | D1 |
| priority | Ordinal | Recorded priority | D1 |
| components, labels | Categorical (multi) | Affected components, tags | D1, D5; graph |
| assignee | Categorical (UUID-masked) | Person who worked the issue | D5 |
| resolution | Categorical | Fixed, Duplicate, Won't Fix, … | D4 (proxy) |
| issuelinks (type, direction, key) | Relational | Duplicate, Relates, Blocks, Causes, … | D2, D6; graph |

| created, resolutiondate | Datetime | Timestamps | Replay (RQ4); time to action |
